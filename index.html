Concurrencia en Programación Orientada a Objetos

1. Procesos vs. Hilos (Threads)

Para entender la concurrencia, primero debemos diferenciar entre un proceso y un hilo de ejecución:

Procesos

  • Los procesos están aislados entre sí.
  • Tienen su propio espacio de memoria.
  • La comunicación entre distintos procesos es compleja y costosa para el sistema operativo.

Hilos (Threads)

  • Existen dentro de un proceso (un proceso puede tener de 1 a n hilos).
  • Los hilos comparten datos y memoria del proceso padre.
  • Permiten ejecutar múltiples tareas simultáneamente de forma más ligera.

2. Implementación de Hilos en Java

Existen dos formas principales de crear un hilo en Java. Ambas requieren definir la lógica que el hilo ejecutará dentro de un método llamado run().

Alternativa 1: Heredar de la clase Thread

Es directo, pero limita tu clase ya que en Java no existe la herencia múltiple.

public class MiHilo extends Thread {
    private int id;
    
    public MiHilo(int id) { this.id = id; }
    
    public void run() {
        System.out.println("Hola, soy " + id);
    }
     public static void main(String[] args) {
        // Uso:
        MiHilo unHilo = new MiHilo(10);
        unHilo.start(); // ¡start() es lo que arranca el hilo nuevo, NO run()!
    }
}

Alternativa 2: Implementar la interfaz Runnable

Es la práctica más recomendada porque deja libre la herencia para otras clases.

class MiHilo implements Runnable {
    private int id;
    
    public MiHilo(int id) { this.id = id; }
    
    public void run() {
        System.out.println("Hola, soy " + id);
    }

    public static void main(String[] args) {
        // Uso:
        MiHilo uno = new MiHilo(10);
        Thread unHilo = new Thread(uno); // Se envuelve el Runnable en un Thread
        unHilo.start();
    }
}

Métodos de Control y Transición

  • start() Invoca la ejecución del hilo. El sistema operativo lo pone en la cola para procesar su run().
  • sleep(ms) Pausa la ejecución del hilo por la cantidad de milisegundos indicada.
  • wait() Suelta el "monitor" (recurso compartido) y pausa el hilo indefinidamente hasta recibir un aviso.
  • notify() / notifyAll() Despierta a uno o a todos los hilos que estaban bloqueados mediante wait().

Otros Métodos y Propiedades

  • join() El hilo que lo llama espera a que este hilo termine por completo para continuar.
  • yield() Cede temporalmente su turno en el procesador a otro hilo.
  • setPriority() Asigna la prioridad de 1 a 10 (MIN_PRIORITY, NORM_PRIORITY, MAX_PRIORITY).

⚠️ Métodos Obsoletos:
Los métodos stop(), suspend() y resume() no deben utilizarse ya que son inseguros y pueden generar interbloqueos (Deadlocks).

4. Recursos Compartidos y Sincronización

Cuando múltiples hilos acceden y modifican un mismo objeto simultáneamente, los datos pueden corromperse. Para evitarlo, usamos la palabra reservada synchronized, la cual proporciona acceso exclusivo (como una llave de una habitación).

Synchronized en Método

Bloquea todo el método para que solo un hilo pueda ejecutarlo a la vez. No se aplica a constructores.

public synchronized void incrementar() {
    contador++; 
}

Synchronized en Objeto

Bloquea solo un bloque de código específico protegiendo un objeto (generalmente this).

public void agregar(String nombre) {
    synchronized(this) {
        this.nombre = nombre;
        this.cantidad++;
    }
}

5. Comunicación: wait, notify y notifyAll

A veces los hilos necesitan coordinarse, no solo bloquearse. Aquí entran los métodos de señalización de la clase base Object (siempre deben usarse dentro de un contexto synchronized, de lo contrario lanzan excepción).

  • wait(): El hilo suelta la "llave" del objeto y se queda dormido esperando que suceda un evento.
  • notify(): Despierta a un hilo cualquiera que estuviera en estado wait() esperando por este objeto. Un notify() disparado si no hay nadie esperando, se pierde.
  • notifyAll(): Despierta a todos los hilos que estaban en wait() por este objeto.

6. El Problema: Productor y Consumidor

Es el problema clásico de sincronización multihilo. Tenemos múltiples hilos Productores que generan datos y los ponen en un Buffer de tamaño fijo ($n$). Al mismo tiempo, múltiples hilos Consumidores extraen esos datos. El Buffer es el recurso compartido.

  • Si el Buffer está lleno, el Productor debe hacer wait().
  • Si el Buffer está vacío, el Consumidor debe hacer wait().
  • Cuando un Productor inserta, hace notify() (por si había un consumidor durmiendo).
  • Cuando un Consumidor extrae, hace notify() (por si había un productor durmiendo).

Paso 1: El Recurso Compartido (Buffer)

class Buffer {
    private int tamanio = 0;
    private double[] buffer = null;
    private int poner = 0, sacar = 0, cantidad = 0;

    public Buffer(int tamanio) {
        this.tamanio = tamanio;
        buffer = new double[tamanio];
    }

    // Método para el Productor
    public synchronized void insertar(double valor) {
        // Se usa un while para volver a chequear la condición tras despertar
        while (cantidad == tamanio) { 
            try { 
                System.out.println("Buffer lleno, productor en espera...");
                wait(); 
            } catch (InterruptedException e) { }
        }
        
        buffer[poner] = valor;
        poner = (poner + 1) % tamanio; // Lógica de buffer circular
        cantidad++;
        
        if (cantidad == 1) {
            // Si estaba vacío y acabo de poner uno, despierto a los consumidores
            notify(); 
        }
    }

    // Método para el Consumidor
    public synchronized double extraer() {
        double valor;
        
        while (cantidad == 0) { 
            try { 
                System.out.println("Buffer vacio, consumidor en espera...");
                wait(); 
            } catch (InterruptedException e) { }
        }
        
        valor = buffer[sacar];
        sacar = (sacar + 1) % tamanio;
        cantidad--;
        
        if (cantidad == tamanio - 1) {
            // Si estaba lleno y acabo de hacer lugar, despierto a los productores
            notify(); 
        }
        return valor;
    }
}

Paso 2: Los Hilos (Productor y Consumidor)

// EL PRODUCTOR
class Productor implements Runnable {
    private Buffer buf;
    
    public Productor(Buffer buf) { this.buf = buf; }
    
    public void run() {
        double item = 0.0;
        while (true) { 
            try { Thread.sleep(500); } catch (Exception e) {}
            buf.insertar(++item);
            System.out.println("Produciendo " + item);
        }
    }
}

// EL CONSUMIDOR
class Consumidor implements Runnable {
    private Buffer buf;
    
    public Consumidor(Buffer buf) { this.buf = buf; }
    
    public void run() {
        double item;
        while (true) {
            item = buf.extraer();
            try { Thread.sleep(500); } catch (Exception e) {}
            System.out.println("Consumiendo " + item);
        }
    }
}

Paso 3: Clase Principal (El Gestor)

public static void main(String[] args) {
    // Instanciamos UN SOLO monitor (recurso compartido) de tamaño 10
    Buffer monitor = new Buffer(10);
    
    // Arrancamos 3 hilos productores simultáneos
    new Thread(new Productor(monitor)).start();
    new Thread(new Productor(monitor)).start();
    new Thread(new Productor(monitor)).start();
    
    // Arrancamos 2 hilos consumidores simultáneos
    new Thread(new Consumidor(monitor)).start();
    new Thread(new Consumidor(monitor)).start();
}

2. Sockets y Streams

Un Socket es el punto final de una conexión de red bidireccional. Está compuesto por dos elementos clave:

Socket = IP + Puerto

Una vez que dos Sockets se conectan (el del Cliente y el del Servidor), se comunican enviando y recibiendo información a través de Streams (flujos de datos).

3. Implementación del Servidor

El servidor debe instanciar un ServerSocket en un puerto específico y quedar a la espera ("escuchando") de conexiones entrantes de clientes. Al aceptar a un cliente, se debe delegar su atención a un hilo nuevo (Thread) para poder seguir esperando nuevos clientes.

ServidorPrincipal.java 
import java.net.*;
import java.io.*;

public class ServidorPrincipal {
    public static void main(String[] args) {
        int PUERTO = 60001; 
        System.out.println("\nArranca Servidor...");
        ServerSocket socketServidor = null;

        try {
            // 1. Abrimos el puerto en el servidor
            socketServidor = new ServerSocket(PUERTO);
        } catch(Exception e) {
            System.out.println(e.getMessage());
        }

        while (true) {
            Socket cliente = null;
            try {
                // 2. El servidor se pausa aquí hasta que se conecta un cliente
                cliente = socketServidor.accept(); 
            } catch(Exception e) {
                System.out.println(e.getMessage());
            }

            // 3. Se delega la conexión a un Hilo (Runnable)
            ServidorEscucha nuevoCliente = new ServidorEscucha(cliente);
            Thread hilo = new Thread(nuevoCliente); 
            hilo.start(); 
            // El ciclo vuelve arriba a esperar otro cliente
        }
    }
}
ServidorEscucha.java (El Hilo de atención) 
public class ServidorEscucha implements Runnable {
    Socket elCliente;
    DataOutputStream salida;
    BufferedReader entrada;
    String leido;

    public ServidorEscucha(Socket cliente) {
        elCliente = cliente; // Guardamos el socket del cliente particular
    }

    public void run() {
        System.out.println("Conexión: IP=" + elCliente.getRemoteSocketAddress() + " Puerto=" + elCliente.getPort()); 
        try {
            // Configuramos Streams de Salida y Entrada
            salida = new DataOutputStream(elCliente.getOutputStream());
            entrada = new BufferedReader(new InputStreamReader(elCliente.getInputStream()));
            
            salida.writeBytes("Hola Cliente!\n"); 
            
            while(true) {
                // Leer del cliente
                leido = entrada.readLine();
                System.out.println("Leido: " + leido);
                // Responder al cliente (Eco)
                salida.writeBytes("Eco del Servidor: " + leido + "\n"); 
            }
        } catch(Exception e) {
            System.out.println(e.getMessage());
        }
    }
}

4. Implementación del Cliente

El cliente necesita instanciar la clase Socket apuntando a la dirección IP del servidor (o localhost si es la misma máquina) y al puerto correcto.

ClienteMain.java 
import java.net.*;
import java.io.*;
import javax.swing.JOptionPane;

public class ClienteMain {
    public static void main(String[] args) {
        int PUERTO = 60001;
        Socket cliente = null;
        String s = "";
        BufferedReader entrada = null;
        BufferedWriter salida = null;

        try {
            // 1. Nos conectamos al servidor
            cliente = new Socket("localhost", PUERTO);
            
            // 2. Configuramos Streams
            entrada = new BufferedReader(new InputStreamReader(cliente.getInputStream()));
            salida = new BufferedWriter(new OutputStreamWriter(cliente.getOutputStream()));
            
            while (true) {
                // Leemos lo que manda el servidor (se bloquea hasta recibir algo)
                while((s = entrada.readLine()).length() == 0) {}
                System.out.println("Servidor dice: " + s);
                
                // Escribimos al servidor usando una ventana gráfica de entrada
                String mensaje = JOptionPane.showInputDialog("Mensaje para enviar:");
                salida.write(mensaje + "\n");
                salida.flush(); // Fuerza el envío de los datos en el buffer
            }
        } catch(Exception e) {
            System.out.println(e.getMessage());
        }
    }
}
Nota sobre el Cliente: En un programa real avanzado de chat, si usamos readLine() en el hilo principal del cliente, bloquearemos la Interfaz Gráfica (UI) impidiendo que el usuario escriba mientras espera recibir un mensaje. Por eso se requiere usar hilos también del lado del cliente.

5. Arquitectura de un Cliente de Chat

Para lograr que un cliente reciba mensajes en tiempo real mientras simultáneamente permite escribir y enviar mensajes, es fundamental dividir las responsabilidades en múltiples hilos (Threads).

El rol de cada Hilo

  • Hilo 1

    Maneja la conexión a nivel de red y mantiene vivo el Socket.

  • Hilo 2

    Se dedica exclusivamente a escuchar la interfaz gráfica (UI) y escribir hacia el OutputStream. Como está en su propio hilo, la UI nunca se congela.

  • Hilo 3

    Posee un bucle infinito escuchando el InputStream. Se queda bloqueado allí, pero como es un hilo separado, no afecta al envío de mensajes.

C# Source Code 
using System;
using System.Collections.Generic;
using System.Linq;
using System.Net;
using System.Net.Sockets;
using System.Text;
using System.Threading.Tasks;
using System.Threading;

namespace servidor1
{
    // Clase encargada de administrar la infraestructura TCP/IP
    class tcpip
    {
        // Colección para mantener referencia a los hilos de cada cliente activo
        List<Thread> thread;

        // Método principal de escucha de conexiones entrantes
        public void escucha()
        {
            thread = new List<Thread>();

            // 1. Obtener la IP local de la computadora (ej. 192.168.3.205)
            IPHostEntry ipHostInfo = Dns.GetHostEntry(Dns.GetHostName());
            IPAddress ipAddress = ipHostInfo.AddressList[1]; // Selecciona la interfaz de red
            
            // 2. Crear el EndPoint en el puerto 11000
            IPEndPoint localEndPoint = new IPEndPoint(ipAddress, 11000);

            // 3. Instanciar el Socket pasándole la familia de la IP, tipo Stream y protocolo TCP
            Socket listener = new Socket(ipAddress.AddressFamily, SocketType.Stream, ProtocolType.Tcp);

            // 4. Vincular el socket con la IP y Puerto e iniciar escucha con cola de hasta 100 peticiones
            listener.Bind(localEndPoint);
            listener.Listen(100);

            Socket cliente;

            // Bucle infinito: Mantiene al servidor listo para aceptar múltiples clientes
            while (true)
            {
                // La ejecución se bloquea aquí hasta que se conecta un cliente
                cliente = listener.Accept();

                // Se crea un nuevo hilo dedicado para atender al cliente sin congelar la escucha
                Thread hilo = new Thread(disparaCliente);
                hilo.Start(cliente); // Se envía el objeto Socket del cliente al hilo
                thread.Add(hilo);
            }
        }

        // Método ejecutado en un hilo independiente para procesar a cada cliente
        public void disparaCliente(Object o)
        {
            Socket param = (Socket)o;

            // 1. Enviar saludo de bienvenida al cliente
            byte[] enviar = Encoding.ASCII.GetBytes("Hola\n");
            param.Send(enviar);

            // 2. Bucle de lectura byte a byte hasta recibir Enter (\r = 13 o \n = 10)
            byte[] recibir = new byte[1];
            string recibido = "";

            param.Receive(recibir, 0);
            
            while (recibir[0] != 13 && recibir[0] != 10)
            {
                // Convierte el byte ASCII recibido a caracter UTF-32 / Unicode
                recibido += char.ConvertFromUtf32(recibir[0]);
                param.Receive(recibir, 0);
            }

            // Imprime en la pantalla del servidor el mensaje completo enviado por el cliente
            Console.WriteLine(recibido);
        }
    }

    class Program
    {
        static void Main(string[] args)
        {
            // Instanciación e inicio del servicio de escucha TCP
            tcpip escucha = new tcpip();
            escucha.escucha();
        }
    }
}

1 Vincular y Escuchar (Bind & Listen)

El método Bind() reserva el puerto 11000 en la dirección IP física del equipo (192.168.3.205). Luego, Listen(100) indica al Sistema Operativo que el socket se pone en modo recepción pasiva, tolerando una cola de hasta 100 clientes simultáneos.

2 Recepción Byte por Byte y Salto de Línea

El método disparaCliente lee un único byte a la vez (byte[1]). El bucle finaliza cuando detecta el byte 13 (Carriage Return \r) o 10 (Line Feed \n), reconstruyendo la palabra enviada e imprimiéndola en consola.

4.2 Definición de la Clase y Constructor

class ServidorTCPIP:
        # El método __init__ establece el estado inicial del servidor.
        # Recibe por defecto la IP de escucha ('102.168.101.24') y el puerto TCP (11000).
        def __init__(self, host='102.168.101.24', port=11000):
            self.host = host
            self.port = port
            
            # DICCIONARIO DE CLIENTES: Estructura compartida en memoria para registrar a los conectados.
            self.clientes = {}  
            
            # OBJETO DE SINCRONIZACIÓN (Lock)
            # Es fundamental en sistemas distribuidos y concurrentes. 
            # Evita "condiciones de carrera" garantizando que solo un hilo a la vez pueda modificar el diccionario de clientes.
            self.lock = threading.Lock()
            
            self.servidor = None

4.3 Inicialización y Bucle Principal (iniciar)

    def iniciar(self):
            # CONFIGURACIÓN DEL SOCKET
            # AF_INET = Protocolo IPv4. 
            # SOCK_STREAM = Protocolo TCP (garantiza entrega, control de flujo y conexión orientada a stream).
            self.servidor = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
            
            # SO_REUSEADDR permite que el puerto sea reutilizado inmediatamente tras cerrar el servidor (evita el error "Address already in use").
            self.servidor.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
            
            # bind(): Enlaza el socket a la IP y Puerto específicos.
            # listen(10): Pone al servidor en modo "escucha", con una cola máxima de 10 conexiones pendientes.
            self.servidor.bind((self.host, self.port))
            self.servidor.listen(10)
            
            logger.info(f"Servidor escuchando en {self.host}:{self.port}")
            
            try:
                # BUCLE PRINCIPAL DE ACEPTACIÓN
                # Este while infinito mantiene al servidor siempre vivo esperando conexiones.
                while True:
                    # accept() es una operación BLOQUEANTE. El hilo principal se detiene aquí hasta que un cliente (Ej: PuTTY) intenta conectarse.
                    # Retorna un nuevo socket específico para ese cliente, y la tupla de su dirección (IP, Puerto de origen).
                    cliente, direccion = self.servidor.accept()
                    logger.info(f"Nuevo cliente conectado desde {direccion}")
                    
                    # DELEGACIÓN CONCURRENTE
                    # Se delega la atención de este nuevo cliente a un hilo (Thread) secundario.
                    # daemon=True significa que el hilo morirá automáticamente si el proceso principal del servidor termina.
                    hilo = threading.Thread(
                        target=self.manejar_cliente,
                        args=(cliente, direccion),
                        daemon=True
                    )
                    hilo.start()
                    
            except KeyboardInterrupt:
                logger.info("Servidor detenido por el usuario")
            finally:
                # Si el while se rompe (ej. Ctrl+C), pasamos a cerrar los sockets abiertos.
                self.cerrar()

4.4 Atención Concurrente y Procesamiento de Comandos (manejar_cliente)

    def manejar_cliente(self, cliente, direccion):
            """Maneja la comunicación con un cliente específico"""
            nombre_cliente = f"{direccion[0]}:{direccion[1]}"
            
            try:
                # SECCIÓN CRÍTICA: Protegida por el Lock.
                # Al usar 'with self.lock', el hilo actual adquiere el cerrojo. Si otro hilo intenta acceder a self.clientes simultáneamente, quedará en espera.
                with self.lock:
                    self.clientes[cliente] = nombre_cliente
                
                # Enviar mensaje de bienvenida. Es necesario codificar (encode) el string a bytes (utf-8) porque los Sockets transmiten Streams binarios.
                cliente.sendall(f"Bienvenido al servidor {nombre_cliente}\n".encode('utf-8'))
                
                while True:
                    recibido = b""
                    datos = ""
                    
                    # LECTURA DE FLUJO (STREAM)
                    # Lee los paquetes entrantes. recv(1024) lee hasta 1024 bytes del buffer del socket.
                    while True:
                        recibido = cliente.recv(1024)
                        
                        if not recibido: # Cliente se desconectó de forma abrupta
                            break
                        
                        if recibido[0] == 13: # 13 = Retorno de carro (\r / Enter presionado en PuTTY)
                            break
                            
                        datos += recibido.decode("utf-8")
                    
                    logger.info(f"📨 Mensaje de {nombre_cliente}: {datos}")
                    
                    # PROCESAMIENTO DE COMANDOS (API INTERACTIVA)
                    if datos.lower() == '#clientes':
                        self.listar_clientes(cliente)
                    elif datos.lower() == '#hora':
                        hora = datetime.now().strftime("%H:%M:%S")
                        cliente.sendall(f"Hora del servidor: {hora}\n".encode('utf-8'))
                    elif datos.lower() == '#salir':
                        cliente.sendall("¡Chau!\n".encode('utf-8'))
                        break
                    else:
                        cliente.sendall(f"Recibido: {datos}\n".encode('utf-8'))
                        
            except Exception as e:
                logger.error(f"Error con cliente {nombre_cliente}: {e}")
            finally:
                # LIMPIEZA FINAL (Desconexión)
                # Entramos nuevamente a la sección crítica (lock) para eliminar al cliente del diccionario de forma segura y liberar su socket.
                with self.lock:
                    if cliente in self.clientes:
                        del self.clientes[cliente]
                cliente.close()
                logger.info(f"Cliente {nombre_cliente} desconectado")

4.5 Métodos Auxiliares y Punto de Entrada Main

    def listar_clientes(self, cliente):
            """Envía la lista de clientes conectados"""
            with self.lock:
                if not self.clientes:
                    cliente.sendall("No hay mas clientes conectados\n".encode('utf-8'))
                    return
                
                lista = "📋 Clientes conectados:\n"
                for _, nombre in self.clientes.items():
                    lista += f"  - {nombre}\n"
                cliente.sendall(lista.encode('utf-8'))
        
        def cerrar(self):
            """Cierra el servidor y todas las conexiones activas iterando sobre el diccionario"""
            if self.servidor:
                with self.lock:
                    for cliente in list(self.clientes.keys()):
                        try:
                            cliente.close()
                        except:
                            pass
                    self.clientes.clear()
                
                self.servidor.close()
                logger.info("Servidor finalizó")

    # PUNTO DE ENTRADA DEL SCRIPT
    if __name__ == "__main__":
        servidor = ServidorTCPIP()
        servidor.iniciar()
