Programación Orientada a Objetos Diseño de Sistemas

Patrones de Diseño de Software

Un Patrón de Diseño es una solución reusable y contrastada a un problema recurrente en el diseño de software orientado a objetos. No es un fragmento de código terminado que se copia y pega, sino una plantilla conceptual para resolver un problema estructural en distintos contextos.

Gang of Four (GoF) — "La Banda de los Cuatro"

El concepto fue popularizado en 1994 por el libro histórico "Design Patterns: Elements of Reusable Object-Oriented Software" escrito por:

Erich Gamma Richard Helm Ralph Johnson John Vlissides

01

Singleton

Patrón Creacional • Examen de Cátedra

★ Presente en PDF Adjunto

Concepto Clave

El patrón Singleton garantiza que una clase tenga una única instancia en todo el ciclo de vida de la aplicación y proporciona un punto de acceso global a ella.

  • Constructor Privado: Impide la instanciación directa mediante new Singleton() desde clases externas.
  • Atributo Estático Privado: Almacena la única referencia a la instancia (private static Singleton instancia).
  • Método Estático Público: Acceso centralizado (obtenerInstancia()) con inicialización perezosa (Lazy Initialization).

Diagrama Memoria / Atributos POO C#

// Clase Singleton (Cátedra)
- valor : int = 1
- instancia : Singleton = null [Static]
+ obtenerInstancia() : Singleton [Static]
+ obtenerValor() : int [Static]

Intentar instanciar directamente: Singleton s2 = new Singleton(); dispara un Error de Compilación debido al constructor privado.

Código Oficial de Cátedra (C# / C-like)

// 1. Definición de la clase con Atributos y Constructor Privado
public class Singleton
{
    private int valor = 1;
    private static Singleton instancia = null;

    // Constructor privado: Nadie puede hacer 'new Singleton()' fuera de esta clase
    private Singleton() { }

    // Método privado auxiliar para instanciar
    private static void crearInstancia()
    {
        if (instancia == null)
        {
            instancia = new Singleton();
        }
    }

    // Punto de acceso público e inicialización perezosa
    public static Singleton obtenerInstancia()
    {
        if (instancia == null) crearInstancia();
        return instancia;
    }

    public static int obtenerValor()
    {
        return instancia.valor;
    }
}

// 2. Prueba de Uso del Singleton
public class Program 
{
    public static void Main() 
    {
        Singleton s1 = null;
        
        // Singleton s2 = new Singleton(); // ❌ Da ERROR DE COMPILACIÓN por ser privado
        
        s1 = Singleton.obtenerInstancia();
        int elValor = Singleton.obtenerValor(); // Devuelve 1
    }
}
Explicación Paso a Paso para Examen
Paso 1: Bloqueo Constructor

Al marcar private Singleton(), el compilador prohíbe que cualquier objeto instancie directamente la clase.

Paso 2: Lazy Initialization

crearInstancia() evalúa si instancia == null. Solo se crea la primera vez que se solicita, ahorrando memoria.

Paso 3: Acceso Centralizado

Todas las llamadas a obtenerInstancia() devuelven la misma dirección de memoria compartida.

02

Composite

Patrón Estructural • Examen de Cátedra

★ Presente en PDF Adjunto

Concepto Clave

El patrón Composite permite componer objetos en estructuras de árbol para representar jerarquías de parte-todo. Permite a los clientes tratar a los objetos individuales (Hoja) y a las composiciones de objetos (Compuesto) de manera uniforme.

  • Composición Recursiva: Un nodo compuesto puede contener tanto hojas como otros nodos compuestos.
  • Componente Base (Abstracto): Define la interfaz común (PatronComposite) con los métodos abstractos: agregar, eliminar y mostrar.
  • Hoja (Leaf): No posee hijos. Bloquea o notifica la imposibilidad de agregar/eliminar.

Estructura Jerárquica en Árbol

📁 Raíz (Compuesto)
├── 📄 Hoja A
├── 📁 SubCarpeta B (Compuesto)
│ ├── 📄 Hoja B.1
│ └── 📄 Hoja B.2
└── 📄 Hoja C

Al invocar mostrar(profundidad) en la raíz, la llamada se propaga recursivamente por todo el árbol imprimiendo los niveles con sangría.

Código Oficial de Cátedra (C#)

// 1. Clase Abstracta Base (Componente)
abstract class PatronComposite
{
    protected String nombre;

    public PatronComposite() { this.nombre = ""; }
    public PatronComposite(String nombre) { this.nombre = nombre; }

    abstract public void agregar(PatronComposite c);
    abstract public void eliminar(PatronComposite c);
    abstract public void mostrar(int profundidad);
}

// 2. Nodo Compuesto (Contenedor de Hijos)
class Compuesto : PatronComposite
{
    private List<PatronComposite> hijo = new List<PatronComposite>();

    public Compuesto() : base() { }
    public Compuesto(String nombre) : base(nombre) { }

    public override void agregar(PatronComposite componente)
    {
        hijo.Add(componente);
    }

    public override void eliminar(PatronComposite componente)
    {
        hijo.Remove(componente);
    }

    public override void mostrar(int profundidad)
    {
        Console.WriteLine(nombre + " nivel: " + profundidad);
        for (int i = 0; i < hijo.Count; i++)
        {
            hijo[i].mostrar(profundidad + 1); // Llamada recursiva
        }
    }
}

// 3. Elemento Hoja (Sin Hijos)
class Hoja : PatronComposite
{
    public Hoja() : base() { }
    public Hoja(String nombre) : base(nombre) { }

    public override void agregar(PatronComposite c)
    {
        Console.WriteLine("no se puede agregar la hoja");
    }

    public override void eliminar(PatronComposite c)
    {
        Console.WriteLine("no se puede quitar la hoja");
    }

    public override void mostrar(int profundidad)
    {
        Console.WriteLine('-' + nombre);
    }
}

Otros Patrones Creacionales Clave

Factory Method (Método Fábrica)

Creacional

Define una interfaz para crear un objeto, pero deja que las subclases decidan qué clase instanciar. Permite diferir la instanciación a las subclases. 

// Interfaz del Producto
public interface INotificador { void Enviar(string msg); }

public class EmailNotificador : INotificador {
    public void Enviar(string msg) => Console.WriteLine("Email: " + msg);
}

// Creador Abstracto (Factory Method)
public abstract class CreadorNotificacion {
    public abstract INotificador CrearNotificador();
}

public class EmailCreador : CreadorNotificacion {
    public override INotificador CrearNotificador() => new EmailNotificador();
}

Abstract Factory Creacional

Proporciona una interfaz para crear familias de objetos relacionados o dependientes sin especificar sus clases concretas. (Ej: Temas UI Oscuro/Claro con Botones y Ventanas emparejadas).

Builder (Constructor) Creacional

Separa la construcción de un objeto complejo de su representación, permitiendo que el mismo proceso de construcción cree diferentes representaciones mediante llamadas encadenadas (Fluent Interface).

Prototype (Prototipo) Creacional

Permite copiar u clonar objetos existentes sin que el código dependa de sus clases concretas. Útil cuando la creación directa de un objeto es costosa en recursos (e.g. acceso a base de datos).

Otros Patrones Estructurales Clave

Adapter (Adaptador)

Convierte la interfaz de una clase en otra interfaz que el cliente espera. Permite que clases con interfaces incompatibles trabajen juntas como un adaptador de enchufe eléctrico.

Decorator (Decorador)

Añade responsabilidades a un objeto de forma dinámica sin modificar su estructura. Alternativa flexible a la herencia para extender funcionalidades (ej: café base + crema + chispas).

Proxy (Apoderado)

Proporciona un sustituto o marcador de posición para otro objeto con el fin de controlar el acceso a él (Proxy de seguridad, Proxy de almacenamiento en caché o Carga perezosa).

Facade (Fachada)

Proporciona una interfaz unificada y simplificada para un conjunto de interfaces en un subsistema complejo.

Patrones de Comportamiento Relevantes

Strategy (Estrategia)

Comportamiento

Define una familia de algoritmos, encapsula cada uno y los hace intercambiables. Permite que el algoritmo varíe independientemente de los clientes que lo utilizan (Ej: Calculadora de Descuentos o Métodos de Pago).

Observer (Observador)

Comportamiento

Define una dependencia uno-a-muchos entre objetos de modo que cuando un objeto cambia de estado, todos sus dependientes son notificados y actualizados automáticamente (Publicador / Suscriptor).

Matriz Resumen de Patrones GoF

Patrón Categoría Propósito Principal Casos de Uso Típicos
Singleton Creacional Garantizar una única instancia global. Conexión a BD, Logger, Gestor de Configuración.
Composite Estructural Tratar objetos individuales y compuestos por igual en árboles. Sistema de archivos, Menús de IU, Organigramas.
Factory Method Creacional Delegar la creación de objetos a subclases. Frameworks extensibles, exportadores de documentos.
Strategy Comportamiento Intercambiar algoritmos en tiempo de ejecución. Cálculo de impuestos, pasarelas de pago, ordenamiento.
Observer Comportamiento Notificar cambios de estado a suscriptores. Eventos de UI, Notificaciones Push, Sistemas Pub/Sub.
