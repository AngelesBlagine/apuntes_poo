Concurrencia en Programación Orientada a Objetos

1. Procesos vs. Hilos (Threads)

Para entender la concurrencia, primero debemos diferenciar entre un proceso y un hilo de ejecución:

Procesos

  • Los procesos están aislados entre sí.
  • Tienen su propio espacio de memoria.
  • La comunicación entre distintos procesos es compleja y costosa para el sistema operativo.

Hilos (Threads)

  • Existen dentro de un proceso (un proceso puede tener de 1 a n hilos).
  • Los hilos comparten datos y memoria del proceso padre.
  • Permiten ejecutar múltiples tareas simultáneamente de forma más ligera.

2. Implementación de Hilos en Java

Existen dos formas principales de crear un hilo en Java. Ambas requieren definir la lógica que el hilo ejecutará dentro de un método llamado run().

Alternativa 1: Heredar de la clase Thread

Es directo, pero limita tu clase ya que en Java no existe la herencia múltiple.

public class MiHilo extends Thread {
    private int id;
    
    public MiHilo(int id) { this.id = id; }
    
    public void run() {
        System.out.println("Hola, soy " + id);
    }
     public static void main(String[] args) {
        // Uso:
        MiHilo unHilo = new MiHilo(10);
        unHilo.start(); // ¡start() es lo que arranca el hilo nuevo, NO run()!
    }
}

Alternativa 2: Implementar la interfaz Runnable

Es la práctica más recomendada porque deja libre la herencia para otras clases.

class MiHilo implements Runnable {
    private int id;
    
    public MiHilo(int id) { this.id = id; }
    
    public void run() {
        System.out.println("Hola, soy " + id);
    }

    public static void main(String[] args) {
        // Uso:
        MiHilo uno = new MiHilo(10);
        Thread unHilo = new Thread(uno); // Se envuelve el Runnable en un Thread
        unHilo.start();
    }
}

Métodos de Control y Transición

  • start() Invoca la ejecución del hilo. El sistema operativo lo pone en la cola para procesar su run().
  • sleep(ms) Pausa la ejecución del hilo por la cantidad de milisegundos indicada.
  • wait() Suelta el "monitor" (recurso compartido) y pausa el hilo indefinidamente hasta recibir un aviso.
  • notify() / notifyAll() Despierta a uno o a todos los hilos que estaban bloqueados mediante wait().

Otros Métodos y Propiedades

  • join() El hilo que lo llama espera a que este hilo termine por completo para continuar.
  • yield() Cede temporalmente su turno en el procesador a otro hilo.
  • setPriority() Asigna la prioridad de 1 a 10 (MIN_PRIORITY, NORM_PRIORITY, MAX_PRIORITY).

⚠️ Métodos Obsoletos:
Los métodos stop(), suspend() y resume() no deben utilizarse ya que son inseguros y pueden generar interbloqueos (Deadlocks).

4. Recursos Compartidos y Sincronización

Cuando múltiples hilos acceden y modifican un mismo objeto simultáneamente, los datos pueden corromperse. Para evitarlo, usamos la palabra reservada synchronized, la cual proporciona acceso exclusivo (como una llave de una habitación).

Synchronized en Método

Bloquea todo el método para que solo un hilo pueda ejecutarlo a la vez. No se aplica a constructores.

public synchronized void incrementar() {
    contador++; 
}

Synchronized en Objeto

Bloquea solo un bloque de código específico protegiendo un objeto (generalmente this).

public void agregar(String nombre) {
    synchronized(this) {
        this.nombre = nombre;
        this.cantidad++;
    }
}

5. Comunicación: wait, notify y notifyAll

A veces los hilos necesitan coordinarse, no solo bloquearse. Aquí entran los métodos de señalización de la clase base Object (siempre deben usarse dentro de un contexto synchronized, de lo contrario lanzan excepción).

  • wait(): El hilo suelta la "llave" del objeto y se queda dormido esperando que suceda un evento.
  • notify(): Despierta a un hilo cualquiera que estuviera en estado wait() esperando por este objeto. Un notify() disparado si no hay nadie esperando, se pierde.
  • notifyAll(): Despierta a todos los hilos que estaban en wait() por este objeto.

6. El Problema: Productor y Consumidor

Es el problema clásico de sincronización multihilo. Tenemos múltiples hilos Productores que generan datos y los ponen en un Buffer de tamaño fijo ($n$). Al mismo tiempo, múltiples hilos Consumidores extraen esos datos. El Buffer es el recurso compartido.

  • Si el Buffer está lleno, el Productor debe hacer wait().
  • Si el Buffer está vacío, el Consumidor debe hacer wait().
  • Cuando un Productor inserta, hace notify() (por si había un consumidor durmiendo).
  • Cuando un Consumidor extrae, hace notify() (por si había un productor durmiendo).

Paso 1: El Recurso Compartido (Buffer)

class Buffer {
    private int tamanio = 0;
    private double[] buffer = null;
    private int poner = 0, sacar = 0, cantidad = 0;

    public Buffer(int tamanio) {
        this.tamanio = tamanio;
        buffer = new double[tamanio];
    }

    // Método para el Productor
    public synchronized void insertar(double valor) {
        // Se usa un while para volver a chequear la condición tras despertar
        while (cantidad == tamanio) { 
            try { 
                System.out.println("Buffer lleno, productor en espera...");
                wait(); 
            } catch (InterruptedException e) { }
        }
        
        buffer[poner] = valor;
        poner = (poner + 1) % tamanio; // Lógica de buffer circular
        cantidad++;
        
        if (cantidad == 1) {
            // Si estaba vacío y acabo de poner uno, despierto a los consumidores
            notify(); 
        }
    }

    // Método para el Consumidor
    public synchronized double extraer() {
        double valor;
        
        while (cantidad == 0) { 
            try { 
                System.out.println("Buffer vacio, consumidor en espera...");
                wait(); 
            } catch (InterruptedException e) { }
        }
        
        valor = buffer[sacar];
        sacar = (sacar + 1) % tamanio;
        cantidad--;
        
        if (cantidad == tamanio - 1) {
            // Si estaba lleno y acabo de hacer lugar, despierto a los productores
            notify(); 
        }
        return valor;
    }
}

Paso 2: Los Hilos (Productor y Consumidor)

// EL PRODUCTOR
class Productor implements Runnable {
    private Buffer buf;
    
    public Productor(Buffer buf) { this.buf = buf; }
    
    public void run() {
        double item = 0.0;
        while (true) { 
            try { Thread.sleep(500); } catch (Exception e) {}
            buf.insertar(++item);
            System.out.println("Produciendo " + item);
        }
    }
}

// EL CONSUMIDOR
class Consumidor implements Runnable {
    private Buffer buf;
    
    public Consumidor(Buffer buf) { this.buf = buf; }
    
    public void run() {
        double item;
        while (true) {
            item = buf.extraer();
            try { Thread.sleep(500); } catch (Exception e) {}
            System.out.println("Consumiendo " + item);
        }
    }
}

Paso 3: Clase Principal (El Gestor)

public static void main(String[] args) {
    // Instanciamos UN SOLO monitor (recurso compartido) de tamaño 10
    Buffer monitor = new Buffer(10);
    
    // Arrancamos 3 hilos productores simultáneos
    new Thread(new Productor(monitor)).start();
    new Thread(new Productor(monitor)).start();
    new Thread(new Productor(monitor)).start();
    
    // Arrancamos 2 hilos consumidores simultáneos
    new Thread(new Consumidor(monitor)).start();
    new Thread(new Consumidor(monitor)).start();
}
